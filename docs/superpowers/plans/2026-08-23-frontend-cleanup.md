# Frontend Cleanup Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove all dead code, unify duplicated patterns (hooks, CSRF interceptor, error extraction, API service), eliminate `any` types and stray console statements, and make lint/typecheck first-class scripts — without any user-visible behavior change except improved error toasts.

**Architecture:** Deletion-first ordering (dead files out before pattern work so diffs stay small), then consolidation onto existing single sources of truth (`src/lib/api.ts`, `src/utils.ts`, generated SDK services, shadcn hook conventions). The biome autofix normalization lands early as its own commit to keep later diffs reviewable.

**Tech Stack:** React 19, TypeScript 5.7, Vite 8, pnpm 11, Biome 2.5, Playwright 1.61.

**Spec:** Conversation requirements 2026-08-23 — "clean the frontend code end to end (thorough scope)". Findings source: exploration report 2026-08-23 (file:line references verified against working tree).

## Global Constraints

- Package manager is **pnpm** — never `npm install`/`npx` for dependency changes; `pnpm add`/`pnpm remove` only. (`npx playwright` inside test scripts is pre-existing and stays.)
- **Never edit anything under `src/client/**`** — it is generated by `pnpm generate-client`. If a type is missing there, work around it locally; do not hand-patch.
- **Never edit anything under `src/components/ui/**`** (shadcn primitives) except the one import fix allowed in Task 4.
- Zero user-visible behavior changes except: error paths that previously only logged now also show a toast.
- Every task ends green: `pnpm typecheck` AND `pnpm lint` AND `pnpm build` pass.
- One commit per task, conventional-commit style.
- Before deleting ANY file in Task 2, re-verify it is unreferenced with the given grep — if referenced, STOP and report instead of forcing.

**Facts established during planning (verified):**
- The generated hey-api client resolves `axiosClient = axios` (the GLOBAL axios default) in `src/client/core/request.ts:308`, so the global-axios interceptor in `main.tsx` is what actually protects ALL SDK mutations today. Do not break this wiring.
- `lib/api.ts` duplicates identical CSRF logic for its own instance.

- [ ] **Step 1: Single implementation** — in `src/lib/api.ts` export:

```ts
const attachCsrfInterceptor = (instance: AxiosInstance): void => {
  instance.interceptors.request.use((config) => {
    const method = (config.method || "get").toLowerCase()
    if (!["get", "head", "options"].includes(method)) {
      const csrf = getCookie("csrf_token")
      if (csrf) {
        config.headers = config.headers ?? {}
        config.headers["X-CSRF-Token"] = csrf
      }
    }
    return config
  })
}
```

Keep the existing richer header-setting variant used by the `api` instance if types demand it — the point is ONE function body, registered twice:

```ts
attachCsrfInterceptor(axios) // global — covers generated SDK traffic
attachCsrfInterceptor(api)   // shared instance — covers raw callers
```

Call `attachCsrfInterceptor(axios)` from module top-level of `api.ts` (it is imported by `main.tsx` indirectly already — VERIFY: if `main.tsx` doesn't transitively import `lib/api` before render, add the import there explicitly and drop the old block). Then delete `main.tsx` lines 21–38 (getCookie + interceptor) and its `axios` import.
